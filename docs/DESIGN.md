### opcode (бывш. Claudia)

Tauri 2 + React + Tailwind 4 + Radix UI + lucide-react + framer-motion + recharts; бэкенд на Rust. Последний коммит —
2026-11-06, проект живой. Скриншотов в репозитории нет (только видео в README); вид восстановлен по коду.

**Как устроен**
- Работа с Claude — **не терминал**: запускает `claude -p --output-format stream-json` и рисует сообщения своими
  виджетами (`StreamMessage`, `ToolWidgets`), ввод — плавающее поле `FloatingPromptInput`.
- Навигация: верхняя панель (`Topbar`: статус Claude Code, кнопки разделов) + **вкладки внутри окна** разных типов
  (`chat | projects | usage | mcp | settings | claude-md | agent…`), а не сайдбар.
- Проекты = папки `~/.claude/projects/*`; сессии проекта — сетка карточек (1–3 колонки) с первым сообщением и временем.
- Отдельные разделы: CC Agents (свои агенты с промптом и правами), Usage Dashboard (карточки-сводки + вкладки
  «по моделям / проектам / дням», графики), MCP Manager, редактор CLAUDE.md, timeline/checkpoints, настройки хуков.
- Вид: почти чёрный фон `oklch(0.10 0.01 240)` с лёгкой синевой, карточки на тон светлее, границы едва заметны,
  монохромный «primary» (светлый текст на тёмном), шрифт Inter, скругления 6–12 px, крупные отступы — «спокойный
  SaaS», плотность низкая.

**Берём**
- Список «Активные сессии Claude» отдельно от истории (`RunningClaudeSessions`) — у нас это верх сайдбара.
- У сессии/чата показывать первое сообщение (если нет заголовка) и относительное время.
- Usage как отдельный экран со сводкой сверху и разбивкой ниже (у нас данные из `ccusage`).
- Индикатор «Claude Code найден / версия» в шапке → у нас в строке состояния (версия Claude на VM + doctor).
- Сдержанную тёмную палитру с малоконтрастными границами и Inter; lucide-иконки; Radix-примитивы для меню/диалогов.

**Не берём**
- Свой чат-рендер поверх `stream-json` — это не-цель PLAN.md: терминал Claude Code остаётся как есть (все режимы,
  слэш-команды, разрешения работают без нашей поддержки). К тому же `-p` не живёт в tmux и умирает с соединением.
- CC Agents, MCP Manager, checkpoints, редактор CLAUDE.md/хуков — дублируют возможности самого Claude Code;
  возможно позже как «Настройки Claude», не в MVP.
- Вкладки разнородного содержимого (usage, settings во вкладках рядом с терминалами) — у нас вкладки только для
  терминалов, служебные экраны — оверлеи.
- Низкую плотность и анимации framer-motion: у нас 20+ чатов и 10+ проектов должны помещаться в сайдбар.
- Локальную модель: opcode читает `~/.claude` на той же машине. У нас данные на VM → только через csagent.

### simple-code-gui (DonutCode)

Electron 33 + electron-vite + React + xterm.js (WebGL) + node-pty; тесты vitest. **На паузе** с 2026-09
(README: «project is not in a good state»). Скриншоты: `assets/main.png`, `main tabbed.png`, `settings 1/2.png`.

**Как устроен (по скриншотам и коду)**
- Слева сайдбар «PROJECTS» ~280 px: **категории** (цветные градиентные плашки DEVELOPMENT / MAINTAINING / UTILITIES
  со счётчиком), внутри — проекты: цветной аватар-буква или эмодзи, имя, путь серым в одну строку с обрезкой,
  стрелка раскрытия → список прошлых сессий. Снизу кнопки «+ make / + add», блок задач (beads), панель голоса,
  ряд иконок (микрофон, звук, расширения, обновить, настройки).
- Центр: **вкладки терминалов** (точка-статус + «Проект — имя-сессии», ~220 px, обрезка) и кнопка
  «плитка» — режим, где терминалы стоят колонками, у каждой своя цветная шапка под цвет проекта.
- Внизу каждого терминала — строка-кнопки `Commands ▴ · Automation ▴ · Session ▴ · Backend ▴`.
- Настройки — модальное окно: 9 тем карточками-превью, папка проектов по умолчанию, разрешения Claude чипами,
  режим разрешений, выбор бэкенда (Claude / Gemini / Codex…).
- Вид: тёмный `#0f1012`-подобный фон, терминал на всю площадь, плотно; акцент «Claude Orange»; много цвета
  на категориях (на наш вкус — перебор).
- Механика: поиск сессий в `~/.claude/projects` по закодированному пути проекта, восстановление открытых вкладок
  (`workspace.json` + backup), «умный» Ctrl+C (копировать при выделении, иначе SIGINT), Ctrl+V с картинками,
  drag&drop файла в терминал, автокопирование выделения, ПКМ-меню копировать/вставить.

**Берём**
- Раскладку целиком: сайдбар проектов + вкладки терминалов, терминал занимает всё остальное, плотная вёрстка.
- Проект раскрывается → его чаты (у нас и как отдельный список «Чаты» по времени).
- Точку статуса на вкладке; вкладка = живая сессия.
- Восстановление вкладок при запуске (`workspace.json`), «умные» Ctrl+C / Ctrl+V, ПКМ-меню в терминале,
  drag&drop файла (у нас: загрузка по SFTP + вставка пути), Ctrl+колесо — масштаб шрифта.
- Настройки одним окном с разделами; превью тем карточками.
- Акцентный тёплый оранжевый (наш токен `accent`, см. §5), но только как акцент, не заливками.

**Не берём**
- node-pty и локальные процессы: у нас PTY — канал SSH, процесс живёт в tmux на VM, вкладка лишь «клиент» tmux.
  Закрыть вкладку ≠ убить Claude.
- Плиточный режим — позже (после MVP), tmux уже умеет сплиты внутри вкладки.
- Категории проектов с цветными плашками, эмодзи-аватары, голос, beads, мульти-бэкенды, мобильный сервер,
  автоустановку Node/Claude — не наши задачи.
- Кнопки-меню под каждым терминалом — у нас действия в палитре Ctrl+K, контекстном меню и тулбаре вкладки.

### Что меняет удалённая VM + tmux (наши отличия от обоих)
- Источник правды — VM. Приложение ничего не знает само: все списки приходят от csagent событиями.
- «Открыть чат» = найти tmux-сессию, где он уже идёт (`~/.claude/sessions/<pid>.json` → поле `tmux` → pane →
  сессия), и подключиться к ней; если не идёт — создать tmux-сессию с `claude --resume <id>`.
- Связь может пропасть в любой момент: каждый экран имеет состояние «нет связи», терминалы переподключаются сами.
- `cc` и ClaudeSpace — равноправные клиенты одних tmux-сессий; ничего не «захватываем».

## 2. Информационная архитектура и навигация

### Карта

```
Окно подключения (до первого успешного входа и при ошибках авторизации)
Главное окно
├── Шапка: статус связи · вкладки терминалов · [RDP] · [⌘ палитра] · [⚙]
├── Сайдбар (слева, скрываемый)
│   ├── Активные        — tmux-сессии (всегда видны, свёрнуты до 5 строк + «ещё N»)
│   └── Переключатель   [Проекты | Чаты | Архив] + поле фильтра
│       ├── Проекты     — папки; раскрытие → чаты проекта
│       ├── Чаты        — все чаты по времени
│       └── Архив       — архивные чаты
├── Центр: терминал активной вкладки (или стартовый экран, если вкладок нет)
├── Правая панель (скрываемая): [Сведения | Файлы* | Git*]   (* — этап 5)
└── Строка состояния: VM · ресурсы · Claude Code + doctor · usage
Оверлеи (модальные, поверх главного окна)
├── Палитра команд (Ctrl+K / Ctrl+Shift+P)
├── Система: Usage · Doctor · Ресурсы и службы
├── Настройки
└── Диалоги: новый чат (выбор папки), переименование, подтверждения, ключ хоста, пароль ключа
```

### Принципы
- **Вкладки — только терминалы.** Служебное (настройки, usage, doctor) — оверлеи, закрываются Esc и не мешают
  терминалам.
- **Выбор ≠ открытие.** Одиночный клик по строке сайдбара выбирает её и показывает сведения в правой панели;
  двойной клик / Enter — главное действие (продолжить чат, перейти в сессию, новый чат в проекте). Так же, как в `cc`:
  стрелки + превью + Enter.
- **Одна сущность — одно главное действие**, остальные — в контекстном меню (ПКМ или кнопка `⋯` при наведении)
  и в палитре. Деструктивные — только с подтверждением.
- **Сайдбар всегда отражает VM** без кнопки «обновить» (события csagent). Кнопка ⟳ в шапке — принудительная
  пересинхронизация (на случай сбоя), F5.
- **Связь между панелями:** активная вкладка подсвечивает свою сессию в «Активных» и свой проект; выбор чата
  в сайдбаре, который открыт во вкладке, показывает значок «открыт» и при Enter переключает на вкладку.

### Сущности и действия (паритет с `cc`)

| Сущность | Главное действие (Enter / двойной клик) | Остальные действия | В `cc` |
|---|---|---|---|
| Активная сессия | перейти во вкладку (открыть, если нет) | переименовать · закрыть (kill) · отключить вкладку | ⏎, r, x |
| Чат | продолжить (или перейти, если уже открыт) | в архив · переименовать · копировать id · открыть папку проекта | ⏎, d |
| Чат в архиве | вернуть из архива | — | a → ⏎ |
| Проект | новый чат (или перейти в сессию, если в проекте идёт Claude) | новый чат всегда · shell · lazygit · открыть в VS Code · показать файлы* | ⏎, s, g, f |
| Сайдбар «Проекты» | — | создать проект · клонировать репозиторий | m, c |
| Глобально | новый чат (выбор папки) | shell в `~` · RDP · Система (usage, doctor, ресурсы, mosh) · настройки | n, S, вкладка «Система» |

`yazi` (`f`) заменяется панелью «Файлы» (этап 5); до неё — пункт «Открыть yazi» запускает его во временной вкладке.

## 3. Экраны

Размеры: окно по умолчанию 1440×900, минимум 960×600. Сайдбар 280 px (220–420, тянется), правая панель 360 px
(280–560), шапка 36 px, строка состояния 24 px. Ширина окна < 1200 px → правая панель по умолчанию скрыта.

### 3.1 Главное окно

```
┌──────────────────────────────────────────────────────────────────────────────────────────────┐
│ ◆ ClaudeSpace  ● VM  │ [◐ MyApp      ×] [◉ game  ×] [● shell ~ ×]  [+▾] │ ⌘K  RDP  ⚙  – □ × │ 36px
├──────────────────────┬────────────────────────────────────────────────────┬──────────────────┤
│ АКТИВНЫЕ          3  │                                                    │ Сведения│Файлы│Git│
│ ◐ MyApp  думает  │                                                    │──────────────────│
│ ◉ game  ждёт ответа  │                                                    │ Перенос MyGame  │
│ ● claude  простаив.  │                                                    │ ~/projects/Game… │
│──────────────────────│        терминал: tmux-сессия «MyApp»           │ main · 2 ч назад │
│ [Проекты|Чаты|Архив] │        (Claude Code во весь размер центра)         │ 34 запроса +120−8│
│ 🔍 фильтр…        ＋ │                                                    │ ◉ открыт: game   │
│ ▾ MyApp  main  5м│                                                    │──────────────────│
│     Вакансии…    1д  │                                                    │ ты: перенеси…    │
│     Резюме…      3д  │                                                    │ claude: готово,  │
│ ▸ MyGame  main ✱ 2ч │                                                    │ перенёс 3 файла… │
│ ▸ webapp         1д  │                                                    │                  │
│ ▸ ~              5д  │                                                    │ [Продолжить]     │
│                      │                                                    │ [В архив] [⋯]    │
├──────────────────────┴────────────────────────────────────────────────────┴──────────────────┤
│ ● vm · CPU 12% · RAM 41% · диск 36% │ Claude 2.1.318 ✓ │ окно 5ч: 1.2M, ещё 2ч10м │ 3 сессии │ 24px
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

Рамка окна — своя (`frame: false`, `titleBarOverlay` для кнопок Windows), шапка перетаскивается (`-webkit-app-region:
drag`), вкладки и кнопки — `no-drag`.

**Шапка**
- Логотип + индикатор связи (`●` зелёный — на связи; жёлтый пульс — подключение; красный — нет связи).
  Клик → поповер: хост, задержка (RTT keepalive), время подключения, «Переподключить», «Отключиться».
- Вкладки: значок статуса + заголовок + `×` (при наведении). Заголовок: имя tmux-сессии; если в ней Claude —
  имя проекта (basename папки чата), подсказка при наведении: заголовок чата, папка, статус. Ширина 120–220 px,
  при переполнении — горизонтальная прокрутка колесом и кнопка `▾` со списком всех вкладок. Перетаскивание
  меняет порядок. ПКМ: переименовать сессию · отключить вкладку · закрыть сессию (kill) · копировать имя.
- `+▾`: клик — новый чат в проекте активной вкладки (или диалог выбора папки); стрелка — меню: новый чат…,
  shell в `~`, lazygit для проекта.
- `⌘K` — палитра; `RDP` — запуск RDP; `⚙` — настройки.

**Сайдбар — «Активные»** (данные: `active_changed`)
- Строка 28 px: значок статуса · имя сессии · справа статус словом (или команда, если не Claude: `bash`, `lazygit`) ·
  `+N` окон, если их больше одного. Подстрока не нужна; подсказка при наведении: папка, «подключено клиентов: N»,
  время активности.
- Порядок: сначала `waiting`, затем `busy`, затем остальные по `activity` (свежие выше).
- Больше 5 — сворачивается, «ещё N» раскрывает. Заголовок секции сворачивает её целиком.
- Сессия, открытая во вкладке, выделена полосой акцента слева.
- Пусто: «Нет запущенных сессий» + кнопка «Новый чат».

**Сайдбар — «Проекты»** (`projects_changed`)
- Строка 28 px: `▸` · значок (●, если в проекте идёт Claude, цвет по статусу) · имя (basename для `~/projects/*`,
  иначе короткий путь `~/…`) · ветка git серым-голубым · `✱` если есть незакоммиченные · справа «5м».
- Раскрытие → чаты проекта (строки 24 px с отступом, как в «Чатах», но без колонки проекта), максимум 10 +
  «все чаты проекта (N)» → переключает на «Чаты» с фильтром по проекту.
- `＋` справа от фильтра → меню «Создать проект… / Клонировать репозиторий…».
- Порядок: по последней активности (max(mtime папки, последний чат)), как в `ccdata.project_dirs`. `~` всегда есть.

**Сайдбар — «Чаты» / «Архив»** (`chats_changed`)
- Строка 40 px, две линии: 1) значок «открыт» (цвет статуса) · заголовок; 2) серым: проект · время · «34 зап.».
  Заголовок: `customTitle` → `alias` (наш, см. §7) → `aiTitle`/summary → первый запрос в кавычках → «‹без названия›».
- Группы по времени: «Сегодня», «Вчера», «На этой неделе», «Раньше» (липкие подзаголовки 20 px).
- Фильтр: подстрока (без учёта регистра и ё/е) по заголовку, проекту, первому запросу. Полнотекстовый поиск по
  содержимому — этап 6 (`search_chats`), до этого внизу списка ссылка «Искать в тексте чатов…» неактивна.
- Виртуализация списка (сотни чатов): `@tanstack/react-virtual`.
- Пусто: «Чатов пока нет»; архив: «Архив пуст»; фильтр без результатов: «Ничего не найдено по «…»».

**Центр**
- Активная вкладка — xterm.js на всю площадь, внутренний отступ 6 px, фон = фону терминала.
- Нет вкладок — стартовый экран: три крупные кнопки «Продолжить последний чат: ‹заголовок›», «Новый чат…»,
  «Shell», под ними 5 последних чатов и подсказка «Ctrl+K — всё остальное».
- Вкладка без связи — терминал затемняется (opacity 0.5), по центру плашка «Нет связи с VM · переподключение
  через 4 с · [Сейчас]». Ввод блокируется (не буферизуем нажатия — их легко отправить не туда).
- Вкладка, чья tmux-сессия исчезла (Claude вышел и сессию закрыли, или kill из `cc`) — плашка «Сессия «game»
  завершена» + «Продолжить чат» (если известен chatId) · «Закрыть вкладку».
- Канал завершился без обрыва связи (`Ctrl+B d`, выход из tmux attach), а сессия жива — плашка «Отключено от
  «game» · [Подключить снова] · [Закрыть вкладку]».
- Вкладка подключается — скелет: «Подключение к «game»…» (спиннер), таймаут 10 с → ошибка с текстом и «Повторить».

**Правая панель — «Сведения»** (контекст = выбранная строка сайдбара, иначе активная вкладка)
- Чат: заголовок, папка, ветка, начат/последний, запросы, строки +/−, размер, id (копируется), «открыт: сессия X,
  статус» и хвост диалога — последние 6 реплик («ты» / «claude», markdown без картинок, обрезка до 600 символов
  на реплику). Кнопки: Продолжить · В архив · ⋯.
- Проект: путь, git (ветка, ahead/behind, список изменённых файлов до 20, последние 8 коммитов), «CLAUDE.md есть»,
  чаты проекта (5), кнопки Новый чат · Shell · lazygit · VS Code.
- Сессия (с 2026-11-09, см. «Отклонения» 13): имя сессии со значком статуса; заголовок чата (тот же приоритет, что в
  списке чатов; клик — показать чат в «Чатах») или «Claude не запущен · bash»; статус с длительностью («думает 2 мин»,
  «ждёт ответа с 14:05», «простаивает»); последний запрос пользователя (до 3 строк, многоточие) и когда отправлен;
  папка, ветка git + `✱`; модель и контекст последнего ответа («opus 4.5 · контекст 85K»); клиенты tmux («только это
  окно» / «это окно и ещё 1» / «2 клиента», подробности в подсказке); «работает 3 ч 10 мин · 2 окна». Кнопки:
  Перейти · Переименовать · Закрыть сессию. Без связи — последние загруженные данные серым.
- Загрузка — скелет; ошибка — строка «Не удалось загрузить: ‹сообщение›» + «Повторить».
- «Файлы» и «Git» (этап 5): дерево проекта через SFTP с ленивой подгрузкой, превью текста/markdown/картинок
  (до 1 МБ), скачать / загрузить перетаскиванием; git — статус и diff файла (через csagent `git_diff`).

**Строка состояния**
- Слева направо: связь (`● vm`, клик = поповер связи) · CPU/RAM/диск (клик → Система → Ресурсы) · версия Claude
  Code + результат quick doctor (`✓` / `⚠ частично` жёлтым / `✕ формат изменился` красным; клик → Doctor) · usage
  5-часового окна (клик → Usage) · «N сессий, M ждут ответа».
- Нет связи: всё серое, кроме связи; значения — последние известные с пометкой «(5 мин назад)» в подсказке.

### 3.2 Подключение и первый запуск

Показывается вместо главного окна при первом запуске и когда подключиться не удалось по причине, которую нужно
решить пользователю (авторизация, ключ хоста). Обрыв сети при работе — **не** этот экран, а оверлеи на вкладках.

```
┌──────────────────────────────── ClaudeSpace ────────────────────────────────┐
│                                                                              │
│                         ◆  Подключение к VM                                  │
│                                                                              │
│   Хост      [ vm  ▾ ]   claude@203.0.113.10:22  (из ~/.ssh/config)            │
│   Ключ      C:\Users\<user>\.ssh\id_ed25519                                  │
│                                                                              │
│   ✓ Конфигурация SSH прочитана                                               │
│   ✕ В ssh-agent нет ключей                                                   │
│     ┌──────────────────────────────────────────────────────────────────────┐ │
│     │ Добавьте ключ в агент Windows один раз (пароль спросят в консоли):   │ │
│     │   ssh-add $env:USERPROFILE\.ssh\id_ed25519              [Копировать] │ │
│     │ Служба OpenSSH Authentication Agent хранит ключ и после перезагрузки.│ │
│     └──────────────────────────────────────────────────────────────────────┘ │
│       [ Проверить снова ]     или     [ Ввести пароль ключа ]                │
│   ○ Ключ хоста                                                               │
│   ○ Агент csagent                                                            │
│                                                                              │
│                       Подробности (лог подключения) ▸                        │
└──────────────────────────────────────────────────────────────────────────────┘
```

Шаги идут списком, каждый: `○` ждёт · спиннер · `✓` · `✕` с объяснением и действиями.

1. **Конфигурация.** Читаем `%USERPROFILE%\.ssh\config` (пакет `ssh-config`), список `Host` без масок. По умолчанию
   `vm` (настройка `connection.host`). Нет файла / нет хоста → форма: хост, порт, пользователь, путь к ключу
   (сохраняется в настройках приложения, не в `~/.ssh/config`).
2. **Авторизация.**
   - Сначала ssh-agent: `\\.\pipe\openssh-ssh-agent`. Агент недоступен (служба остановлена) → «Служба OpenSSH
     Authentication Agent не запущена» + команда для админ-PowerShell `Start-Service ssh-agent` (кнопка
     «Копировать»; сами не запускаем).
   - Агент пуст → блок выше: подсказка `ssh-add` **или** «Ввести пароль ключа».
   - «Ввести пароль ключа» → поле пароля (маскированное, `Enter` — войти). Ключ расшифровывается в main
     (`ssh2.utils.parseKey(buf, passphrase)`), **держится в памяти процесса до выхода** (для переподключений),
     на диск и в настройки не пишется. Неверный пароль → «Пароль не подошёл» под полем.
   - Сервер отверг ключ → «VM не приняла ключ ‹отпечаток›. Проверьте authorized_keys».
3. **Ключ хоста.** Ищем в `%USERPROFILE%\.ssh\known_hosts` (поддержать хэшированные `|1|…` и `[host]:port`),
   затем в `userData/known_hosts` приложения.
   - Не найден → диалог: «Первое подключение к 203.0.113.10. Отпечаток SHA256:… Совпадает с тем, что показывает
     `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` на VM?» [Доверять] [Отмена]. «Доверять» пишет только в
     `userData/known_hosts`, `~/.ssh/known_hosts` не меняем.
   - Не совпал → красный экран-стоп «Ключ VM изменился. Возможна подмена. Подключение отменено.» без кнопки
     «всё равно подключиться»; инструкция: удалить строку в known_hosts вручную, если переустанавливали VM.
4. **Агент csagent.** Проверка версии → при необходимости установка (§7.7) с прогрессом «Установка агента
   (12 КБ)…» → запуск → `hello`. Ошибки: «На VM нет python3» / «На VM нет tmux» / «Агент не ответил за 10 с»
   + кнопка «Показать лог».
5. Успех → главное окно; восстановление вкладок (§4.1).

Сеть недоступна (таймаут, ECONNREFUSED, DNS) на этом экране → «VM недоступна: ‹причина›. Повтор через N с»
с обратным отсчётом (та же экспоненциальная задержка) и «Повторить сейчас».

«Подробности» — лог последних 200 строк подключения (`ssh2` debug без секретов) с кнопкой «Копировать».

          ├────────────────────────────────────────────────────────────┤
          │ ЧАТЫ                                                        │
          │ ◉ Перенос MyGame               MyGame · 2ч   ⏎ продолжить │

## 4. Сценарии

### 4.1 Открыть приложение → продолжить чат
1. Запуск → main читает настройки и `workspace.json` → окно сразу показывает каркас с прошлыми вкладками
   (из кэша `userData/cache/snapshot.json`: последние списки сайдбара, помечены серым «обновляется…»).
2. Подключение (ssh-agent) → csagent `hello` → `list_active`, `list_projects`, `list_chats` → сайдбар живой.
3. Для каждой сохранённой вкладки типа `claude`/`tmux`: сессия есть в `list_active` → открыть PTY-канал
   `tmux attach`; нет → плашка «Сессия завершена» (§3.1). Временные вкладки (shell, lazygit) не восстанавливаются.
4. Пользователь видит в «Активных» `◉ game ждёт ответа` → двойной клик → вкладка активна, фокус в терминале.
   Или в «Чатах» двойной клик по закрытому чату → `new_session {cwd, resume: chatId}` → агент создаёт tmux-сессию
   `claude --resume <id>; exec bash -l` → ответ `{session: "MyGame"}` → новая вкладка `tmux attach -t =MyGame`.
5. Готово, когда: от запуска до живого терминала ≤ 3 с при работающем агенте ssh.

### 4.2 Новый чат в проекте
- Проект → Enter (или `+` в шапке, Ctrl+Shift+N, палитра «Новый чат в …»). Если в проекте уже идёт Claude —
  Enter переводит в эту сессию; «Новый чат» из меню всегда создаёт новую.
- `new_session {cwd}` → имя сессии по правилам `cc` (basename, `[A-Za-z0-9_-]`, ≤ 20, суффикс `-2`, `-3`) →
  вкладка. Ответ агента приходит до появления сессии в `active_changed` — вкладку открываем по ответу, не ждём события.
- «Новый чат…» без проекта → диалог выбора папки: список `list_dirs` (как `ccdata dirs`) с фильтром + «Другая
  папка…» (поле пути, по умолчанию `~/projects/`; если папки нет — «Создать?» → `create_project`).

### 4.3 Чат уже открыт в `cc` (или в другой вкладке)
- csagent знает соответствие чат → pane → tmux-сессия (`sessions/*.json` → `tmux: "MyApp:@10.%10"` → pane `%10`).
  В чате значок «открыт» цвета статуса, в «Сведениях» — «открыт в сессии MyApp (ещё 1 клиент)».
- Enter на таком чате → **не** запускаем второй `claude --resume` (это испортило бы транскрипт), а открываем вкладку
  с `tmux attach -t =MyApp` и выбираем нужное окно (`select-window` делает агент: `focus_window`).
- Два клиента tmux одной сессии — нормально. Размер окна берётся от последнего активного клиента
  (`window-size latest`, на VM уже так). Переключение на вкладку в приложении шлёт ресайз → окно подстраивается.
- Если чат открыт вне tmux (терминал в RDP) — `tmux` в реестре пуст: Enter показывает диалог «Чат открыт вне tmux
  (pid 1234). Открыть вторую копию нельзя. [Понятно]».

### 4.4 Обрыв сети и восстановление
1. ssh2 `keepaliveInterval: 15000`, `keepaliveCountMax: 3` → обрыв замечен ≤ 45 с (или сразу по ошибке сокета).
   Windows `powerMonitor.on('resume')` и `online` → немедленная проверка/переподключение.
2. Все вкладки → оверлей «Нет связи», ввод блокирован; сайдбар и строка состояния — серые, данные последние;
   действия, требующие VM, неактивны.
3. Переподключение: задержки 1, 2, 4, 8, 16, 30, 30… с (± 20% разброс), счётчик в оверлее и кнопка «Сейчас».
   Авторизация: агент ssh или ключ, расшифрованный в памяти; если агент пуст (ключ удалили из агента) и пароля в
   памяти нет — переход на экран подключения шагом «Авторизация».
4. Успех → новый csagent, полная загрузка списков (снимки, не дельты) → каждая вкладка переподключается
   (`xterm.reset()` + новый канал `tmux attach`; tmux перерисует экран целиком). Claude всё это время работал.
5. Тост «Связь восстановлена (не было 2 мин)». Сайдбар показывает изменения, которые произошли без нас.

### 4.5 Claude ждёт ответа → уведомление Windows
- Источник: поле `status` в `~/.claude/sessions/<pid>.json` (`busy` / `waiting` / `idle`), агент опрашивает раз
  в секунду и шлёт `session_status` при смене.
- Правила (main, модуль `notify.ts`):
  - `* → waiting`: уведомление «Claude ждёт ответа — MyGame» с текстом последнего сообщения Claude (из хвоста
    чата, ≤ 120 символов), если окно не в фокусе **или** эта вкладка не активна.
  - `busy → idle` (закончил): уведомление «Claude закончил — MyGame», если включено в настройках (по умолчанию
    выкл) и выполнялся > 30 с.
  - Не чаще одного уведомления на сессию в 10 с; повторное `waiting` после `busy` — снова уведомляем.
- Клик по уведомлению → окно на передний план, вкладка этой сессии (открыть, если нет), фокус в терминал.
- Дополнительно: `win.flashFrame(true)` пока окно не в фокусе; значок-наложение на кнопке панели задач с числом
  ждущих (`setOverlayIcon`, рисуется на canvas); значок вкладки и строки «Активных» — цвет `waiting`.
- `app.setAppUserModelId('ClaudeSpace')` обязательно, иначе тосты Windows не показываются.
- Хук на VM (`~/.claude/hooks/notify.sh`, Telegram) не трогаем — он работает независимо (для телефона).
- Этап 6; в MVP — только цвет статуса на вкладке и в сайдбаре.

### 4.6 RDP по кнопке
- `RDP` в шапке / палитра «Открыть рабочий стол VM (RDP)».
- main: проверить, что файл из настройки существует → `spawn('powershell.exe', ['-NoProfile', '-ExecutionPolicy',
  'Bypass', '-File', path], { detached: true, windowsHide: true, stdio: 'ignore' }).unref()`.
- Тост «Запускаю RDP…»; файла нет → тост-ошибка «Не найден C:\…\connect-rdp.ps1 — путь в Настройках →
  Интеграции». Код выхода не ждём (скрипт сам держит туннель и mstsc). Пароль RDP приложение не видит.
- Работает и без связи с VM (скрипт сам поднимает туннель).

### 4.7 Открыть проект / файл в VS Code (Remote-SSH)
- Проект: `code --folder-uri vscode-remote://ssh-remote+<host>/home/claude/projects/X`;
  файл (этап 5): `code --file-uri vscode-remote://ssh-remote+<host>/<path>`. `<host>` — Host из настроек
  «Интеграции» (по умолчанию тот же alias `vm`), путь URL-кодируется по сегментам.
- Запуск через `spawn` с `shell: false`; `code` ищем в PATH (`where.exe code`) и в
  `%LOCALAPPDATA%\Programs\Microsoft VS Code\bin\code.cmd`. Нет → тост «VS Code не найден» + ссылка на настройку.
- Проверить на этапе 4: установлены ли на ПК VS Code и расширение Remote-SSH (`code --list-extensions`).

### 4.8 Прочие сценарии MVP
- **Shell / lazygit в проекте** → временная вкладка: PTY-канал без tmux, команда `cd <dir> && exec bash -l` /
  `exec lazygit -p <dir>`. Закрытие вкладки завершает процесс (предупреждать не нужно). Значок вкладки — серый.
- **Закрыть сессию** → диалог «Закрыть сессию «game» и всё, что в ней запущено?» (если Claude `busy` — красным:
  «Claude сейчас работает») [Закрыть] [Отмена] → `kill_session`. Вкладка закрывается сама по `active_changed`.
- **Закрыть вкладку (×, Ctrl+Shift+W)** — только отключает клиента tmux, сессия живёт. Подсказка при первом
  закрытии: «Сессия продолжает работать на VM. Закрыть её совсем — ПКМ → Закрыть сессию».
- **Архив** → `archive_chat`; открытый чат архивировать нельзя (агент вернёт `chat_open`) → тост «Сначала закройте
  чат». Отмена: тост «В архиве: ‹заголовок›» с кнопкой «Вернуть» (5 с).
- **Создать проект** → диалог: путь (по умолчанию `~/projects/`), флажок `git init` → `create_project`.
- **Клонировать** → диалог URL + папка → временная вкладка с `git clone <url> <dest>` (чтобы работали запросы
  пароля/ключа), по завершении в вкладке плашка «Готово. [Новый чат в ‹dest›]».

## 6. Горячие клавиши

Принцип: **терминал важнее приложения.** Всё, что значимо для bash/readline, tmux (префикс `Ctrl+B`, `Alt+стрелки`)
и Claude Code (`Ctrl+C`, `Esc`, `Shift+Tab`, `Ctrl+R`, `Ctrl+O`, `Ctrl+T`, `Ctrl+L`, `Ctrl+W`, `Ctrl+K`…), уходит в

## 7. Протокол csagent

### 7.1 Транспорт
- Запуск: `ssh exec` без PTY: `exec python3 -I ~/.local/lib/claudespace/csagent.py serve --protocol 1`.
- Кадры — **JSON Lines** в UTF-8: один объект на строку, `\n` в конце, без переносов внутри (`ensure_ascii=False`,
  `separators=(',', ':')`). stderr агента — лог (main пишет его в свой лог с префиксом `[agent]`).
- Максимальный размер кадра 4 МБ (больше — агент отвечает ошибкой `too_large`).
- Агент однопоточный цикл: `selectors` на stdin + таймеры опроса. Долгие запросы (ccusage, git по многим
  проектам, doctor) — в `ThreadPoolExecutor(max_workers=2)`, ответ приходит, когда готов; порядок ответов не
  гарантирован, сопоставление по `id`.
- Агент завершается при EOF на stdin (соединение закрылось) — ничего не остаётся висеть. Повторный запуск при
  уже работающем агенте того же соединения не нужен; от разных соединений агенты независимы (лок не нужен,
  кроме записи кэша — атомарная замена файла).

### 7.2 Кадры

```jsonc
// запрос (app → agent)
{"id": 17, "method": "list_chats", "params": {"archived": false}}
// успех
{"id": 17, "result": {"chats": [ ... ]}}
// ошибка
{"id": 17, "error": {"code": "not_found", "message": "чат не найден", "data": {"chatId": "…"}}}
// событие (agent → app), без id
{"event": "session_status", "data": {"chatId": "7a6a…", "session": "MyApp", "status": "waiting", "prev": "busy", "at": 1794159620160}}
```

Коды ошибок: `bad_request` (неизвестный метод, неверные params), `not_found`, `exists`, `chat_open`,
`not_allowed` (путь вне разрешённых, запрещённый файл), `tmux_error`, `timeout`, `too_large`, `internal`.
Текст `message` — по-русски, его можно показывать пользователю как есть.

Время везде — миллисекунды Unix (`number`), пути — абсолютные строки на VM.

### 7.3 Рукопожатие и версии
Сразу после запуска агент шлёт:
```json
{"event": "hello", "data": {"protocol": 1, "agent": "0.1.0", "hash": "sha256:9f2c…", "python": "3.12.3",
 "host": "claude-vm", "user": "claude", "home": "/home/claude", "claudeVersion": "2.1.318",
 "tmux": "3.4", "capabilities": ["usage", "git", "mosh"], "warnings": []}}
```
- `protocol` — целое; меняется только при несовместимых изменениях. Приложение знает свой `PROTOCOL = 1`; если
  `hello.protocol` другой — переустанавливает агент из своей поставки (§7.7). Добавление методов/полей —
  совместимо, `protocol` не меняется (неизвестные поля приложение игнорирует, неизвестные события — тоже).
- `agent` — semver агента; `hash` — sha256 содержимого установленных файлов (манифест).
- `capabilities` — опциональные возможности (нет `ccusage` → нет `usage`).
- `warnings` — например `["tmux не найден"]`; приложение показывает их на экране подключения.

### 7.5 События

| Событие | data | Когда |
|---|---|---|
| `hello` | см. §7.3 | при старте |
| `active_changed` | `{sessions: Session[]}` — **полный снимок** (сессий мало) | изменился список tmux-сессий, имена, attached, окна или статусы Claude |
| `session_status` | `{session, chatId, status, prev, at}` | смена статуса Claude (`busy/waiting/idle`); дублирует часть `active_changed`, но дешевле для уведомлений |
| `chats_changed` | `{upsert: Chat[], remove: string[]}` — дельта; после `resync` и при старте — `{full: Chat[]}` | новый/изменённый/удалённый/перенесённый в архив транскрипт, сменился «открыт» |
| `projects_changed` | `{full: Project[]}` | новая/удалённая папка, сменились ветка/грязность/активность |
| `system` | `SystemStats` | раз в 10 с |
| `doctor_warning` | `{level: "ok"|"warn"|"error", message}` | при старте (quick doctor) и при смене версии Claude Code |
| `ports_changed` | `{ports: VmPort[]}` — полный снимок | при старте и при изменении (опрос раз в 3 с) |
| `winfs_changed` | `{mounts: [{dst, src, owned}]}` — полный снимок | при старте и при изменении (опрос `/proc/self/mountinfo` раз в 5 с) |

Опрос в агенте (только stdlib, без inotify):
- `~/.claude/sessions/*.json` — раз в 1 с: `os.scandir` + `stat` (mtime/size), читаем только изменившиеся `*.json`
  (файлы `*.key` в этой папке **не открываем**), проверка живости pid по `/proc/<pid>/stat` + `procStart`.
- `tmux list-sessions` / `list-panes -a` — раз в 2 с (и сразу после своих `new/kill/rename`).
- транскрипты — раз в 3 с: `glob` + `stat`, разбор только изменившихся (`ccdata.parse_chat` с индексом-кэшем).
- git — для проектов, раз в 30 с, только если mtime папки или `.git/index` изменился; `timeout 2` на вызов.
- События шлются только при изменении (сравнение с прошлым снимком), не чаще 4 раз в секунду на тип (склейка).

### 7.6 Правила безопасности агента
- Никогда не читает: `~/.claude/.credentials.json`, `~/.claude/settings.local.json`, `~/.claude/history.jsonl`,
  `~/.claude/sessions/*.key`, всё в `~/.ssh`. Это проверяется тестом (фикстура с «секретами» + проверка, что агент
  их не открывает: `open` обёрнут в функцию с запрет-списком).
- В общую библиотеку **не** переносится `ccdata.tg_send` (он читает `settings.local.json`): Telegram-уведомления
  doctor остаются в `ccdata.py` для `cc`.
- Нет метода «выполнить команду». tmux вызывается через `subprocess.run([...])` списком аргументов, без shell.
  В команде новой tmux-сессии (это строка для shell внутри tmux) все подстановки — `shlex.quote`.
- Имена сессий: санитизация как в `cc` (`[A-Za-z0-9_-]`, ≤ 32), цель tmux всегда `=<name>` (точное совпадение).
- Пути (`cwd`, `path`): `os.path.realpath`, должны существовать и лежать в `$HOME` (для `new_session`,
  `create_project`, `project_preview`, git). `chatId` — только `[0-9a-f-]{36}`, ищется в индексе, путь к файлу не
  принимается от клиента.
- Переименование чата не трогает транскрипт: псевдонимы в `~/.local/state/claudespace/titles.json`
  (`{chatId: title}`); `cc` их тоже показывает (через общую библиотеку).
- Архив — тот же каталог, что у `cc`: `~/.claude/cc-menu-archive/<project>/`.
- Окружение для `claude` в новой сессии: `unset CLAUDECODE CLAUDE_CODE_ENTRYPOINT`, `PATH=~/.local/bin:$PATH`,
  команда `claude [--resume <id>]; exec bash -l` — как в `cc`.

### 7.7 Установка и обновление агента
- Поставка: файлы агента лежат в приложении (`resources/agent/`: `csagent.py`, `cclib/*.py`, `MANIFEST.json`
  с версией, `protocol` и sha256 каждого файла и общим `hash`).
- При каждом подключении main выполняет:
  `exec cat ~/.local/lib/claudespace/MANIFEST.json 2>/dev/null` → сравнивает `hash` со своим.
- Не совпало / нет файла → SFTP: загрузить в `~/.local/lib/claudespace.tmp-<rand>/`, проверить sha256
  (`exec python3 -I -c 'import hashlib…'` по манифесту), затем атомарно: `mv` старой папки в
  `claudespace.old`, `mv` новой на место, `rm -rf claudespace.old`. Права `0700` на папку, `0600/0700` на файлы.
- Нет `python3` (≥ 3.8) или `tmux` → ошибка на экране подключения, ничего не ставим.
- Откат не нужен: версия агента всегда та, что в приложении.
- Разработка: `npm run agent:install` на VM копирует `agent/` в `~/.local/lib/claudespace/` напрямую (тот же
  манифест), `cc` после шага 1 использует ту же библиотеку (см. ниже).

**Общая библиотека с `cc` (этап 1).** Исходник — `agent/cclib/` в этом репозитории, установка —
`~/.local/lib/claudespace/cclib/`. `~/.local/lib/cc-menu/ccdata.py` становится «рендером»: импортирует
`cclib` из `~/.local/lib/claudespace` (если его нет — понятная ошибка «установите агент: …»), оставляет у себя
форматирование для fzf, Telegram и `doctor --notify`. Изменение `ccdata.py` — вне этого репозитория: делать с
бэкапом и проверкой, что `cc` работает (этап 1, чек-лист). Кэш индекса чатов у агента свой —
`~/.cache/claudespace/chats.json` (формат = `ccdata` `INDEX_VERSION 3`), чтобы два процесса не мешали друг другу.

**Ключевые решения по модулям**
- **IPC:** renderer не видит ssh2 и Node. `window.cs.invoke('agent.call', {method, params})` — main проверяет
  `method` по списку из `shared/protocol.ts` и params по zod-схеме. Терминалы: `term.open({tabId, kind, session|cwd,
  cols, rows})`, `term.write`, `term.resize`, `term.close`; данные из main — событие `term.data` с `Uint8Array`,
  склейка по 8 мс; когда в renderer необработанных > 1 МБ — `stream.pause()` до подтверждения `term.ack`.
- **Терминальный канал:** `conn.exec(cmd, { pty: { term: 'xterm-256color', cols, rows }, env: { LANG: 'C.UTF-8' } })`
  (env может не пройти через sshd `AcceptEnv` — тогда префикс `LANG=C.UTF-8` в самой команде).
  `cmd` для tmux: `exec tmux -u attach-session -t '=<name>'`; имя валидируется regex'ом `^[A-Za-z0-9_-]{1,32}$` в main.
  Ресайз: `fit` → `stream.setWindow(rows, cols, 0, 0)` с дебаунсом 50 мс.
- **Electron-безопасность:** `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`,
  CSP `default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:`; `will-navigate` и

- **Логи:** `userData/logs/main.log` (ротация 5×1 МБ), без паролей, ключей и содержимого терминалов.

## Отклонения от диздока

Записано при реализации MVP (этапы 0–4), 2026-11-08. Подробности — [DEV.md](DEV.md).

1. **Транспорт заменяемый, есть локальный режим.** Кроме ssh2 есть `LocalTransport` (команды на этой же машине,
   PTY через `resources/ptyhelper.py` на Python stdlib — без нативного node-pty). Настройка `connection.mode`:
   `ssh` (по умолчанию в Windows) / `local` (по умолчанию в Linux, для разработки на VM без ключа в `authorized_keys`).
   Шаги «Авторизация» и «Ключ хоста» в локальном режиме пропускаются.
2. **Агент сам шлёт полные снимки после `hello`** (`active_changed`, `chats_changed {full}` — вместе с архивными,
   `projects_changed`), приложение не вызывает `list_*` при подключении. `resync` делает то же по запросу (F5).
3. **`cc` не переведён на `cclib`** (пункт этапа 1): правка `~/.local/lib/cc-menu/ccdata.py` требует согласия
   пользователя. Следствие: псевдонимы чатов (`rename_chat`, `~/.local/state/claudespace/titles.json`) пока видны
   только в ClaudeSpace. Состояние doctor у агента своё (`~/.local/state/claudespace/compat.json`), чтобы не мешать
   Telegram-уведомлениям `cc` о смене версии.
4. **Порядок заголовков:** `customTitle` (своё `/rename` в Claude Code) важнее нашего псевдонима — чтобы
   переименование в самом Claude не терялось. Дальше — как в §3.1.
5. **Аудит-хук вместо обёртки `open`:** запрет-список (§7.6) действует на весь процесс агента через
   `sys.addaudithook` (open/listdir/scandir), плюс явный `safe_open`. Тест проверяет все попытки открыть файл за
   полный прогон всех методов.
6. **Шрифты** лежат в `resources/fonts` (woff2 из `@fontsource-variable/*`, OFL) и встраиваются vite в сборку
   renderer, а не грузятся из `resources` во время работы.
7. **Без `@xterm/addon-search` UI-панели:** поиск — простой диалог «найти следующее» (shell-вкладки); в tmux-вкладках
   подсказка про copy-mode, как в §6.
8. **Подсказки (tooltip)** — нативный `title`, а не Radix Tooltip (меньше кода, то же поведение).
9. **Кнопка «Вставить» при > 5 строк** показывает превью первых 30 строк.
10. **Проверка «ключ хоста изменился»** считает несовпадением только ключ того же типа, что уже записан для хоста
    (как OpenSSH); ключ другого типа — «новый ключ» с вопросом.
11. **Разработка на этой VM:** Chromium-песочница Electron требует setuid `chrome-sandbox` (нужен sudo), а
    Ubuntu 24.04 запрещает user namespaces для непривилегированных (`apparmor_restrict_unprivileged_userns=1`). Поэтому
    на VM Electron запускается с `--no-sandbox` (`npm run dev:vm`, e2e). В коде `sandbox: true` остаётся; на Windows
    флаг не нужен.
12. В §10 текст был повреждён (склеены «Готово, когда» этапа 2 и начало этапа 3) — восстановлен заголовок
    «Этап 3 — терминал» и первый пункт.
13. **«Сведения» сессии без снимка экрана** (2026-11-09, BACKLOG 3): хвост `capture-pane` дублировал терминал. Метод
    `session_preview` теперь отдаёт `SessionDetails` (`src/shared/model.ts`): свежую `Session`, `created`
    (`session_created`), `clients` (`list-clients`: tty, term, размер, активность), `git` папки сессии (кэш по mtime)
    и для каждого Claude в сессии — `chat` (модель `Chat`), `lastPrompt {text ≤ 500, at}`, `model` и `context
    {tokens, output}` из `usage` последнего ответа ассистента (`chats.tail_info`: читается только хвост 256 КБ, при
    необходимости 2 МБ). Параметр `lines` и поле `text` убраны, `tmux.capture` удалён. `protocol` не менялся:
    приложение и агент ставятся одной поставкой (§7.7, сверка `hash`). Метод перенесён в пул долгих (git).
14. **Обратный туннель и «Диск ПК»** (2026-11-09, BACKLOG 12). `src/main/pclink.ts`, агент `cclib/winfs.py`,
    `cclib/netstat.py`. Решения:
    - Туннель слушает только `127.0.0.1:2222` на VM (внешний туннель может держать ещё и `[::1]:2222`; `Host` с
      `HostName localhost` при отказе на `::1` сам переходит на `127.0.0.1`). Перед `forwardIn` агент смотрит
      `/proc/net/tcp`: занятый порт не пытаемся занять (иначе sshd пишет «Address already in use» в журнал каждые
      15 с). Порт отвечает баннером `SSH-` → «внешний туннель», нет → «порт 2222 занят» (например, наш же
      прошлый сеанс, который sshd снимет по `ClientAliveInterval 60 × 3`). Зависшего владельца не убиваем.
    - Отключение диска — `fusermount3 -u <папка>`, а не `winfs -u`: тот отключает все `~/winfs/*`, в том числе
      подключённые вручную. Подключение — через `winfs` пользователя (его опции sshfs: `reconnect`,
      `ServerAlive 15×3`).
    - «Свой» диск определяет агент по id монтирования (`~/.local/state/claudespace/winfs.json`), поэтому
      подключённое вручную (до приложения или потом в ту же папку) автоматически не отключается. Явное «Отключить
      диск» из меню отключает и ручной (пункт помечен «подключён вручную»).
    - Зависания sshfs: при выходе и «Отключиться» приложение лениво (`-z`) отключает свои диски; если приложение
      пропало (обрыв, сбой), это делает агент при EOF — только диски, которыми владеет его pid (новый агент после
      переподключения перехватывает владение, и старый их не трогает). Пока соединение живо, туннель не падает;
      если sshd на ПК остановлен, канал отклоняется сразу и sshfs получает ошибку, а не зависание.
    - Новые методы помечены `MAIN_ONLY_METHODS`: renderer не вызывает их через `agent.call`, только через
      `pclink.*` (main хранит, что подключило приложение). `protocol` не менялся (§7.7).
15. **Проброс портов VM → ПК** (2026-11-09, BACKLOG 10). `src/main/ports.ts`, `src/shared/ports.ts`, агент
    `cclib/netstat.py` (`PortScanner`). Решения:
    - «Порты» — вкладка правой панели (рядом со «Сведениями»), а не секция сайдбара: сайдбар про сессии/чаты.
    - Слушатель на ПК — только `127.0.0.1`, `exclusive`; тот же номер, иначе следующий из 20, иначе любой свободный.
      Другой номер — сообщение пользователю (dev-серверы бывают привязаны к Host/порту).
    - На VM соединение идёт на `127.0.0.1`, но на `::1`, если процесс слушает только `::1` (vite с `localhost` в
      новых Node) — это тоже loopback; внешние адреса VM не используются.
    - В порты не попадают: чужие процессы (другой uid), `sshd`, порт туннеля 2222, сокеты на не-loopback адресах.
    - Пробросы не закрываются при обрыве (слушатель остаётся, новые соединения идут по новому SSH), закрываются при
      выходе. Закреплённые (`settings.ports.pinned`) поднимаются при каждом подключении.
    - Локальный режим (разработка на VM): слушатель не нужен, адрес открывается как есть.
    - Ссылки в терминале: обрабатываются только `http(s)://localhost|127.0.0.1|0.0.0.0|[::1]:N/…`, остальные — как
      раньше (`launch.openExternal`).
16. **Пароль sudo в приложении** (2026-11-14, BACKLOG 11). Агент `cclib/askpass.py` (`AskpassServer`), скрипт
    `agent/askpass.py` (ставится в бандле как `~/.local/lib/claudespace/askpass.py`, `0700`), main `src/main/askpass.ts`,
    renderer `askpass.ts`, `stores/askpass.ts`, `components/Overlays/AskpassDialog.tsx`. Решения:
    - Сокет — `~/.cache/claudespace/run/askpass.sock` (папка `0700`, сокет `0600`), а не `$XDG_RUNTIME_DIR`: у агента
      (SSH exec, tmux-сервер, локальный режим) и у `sudo` из разных мест эта переменная может отличаться или
      отсутствовать, а `HOME` один. Каждый клиент проверяется `SO_PEERCRED` (только свой uid).
    - Сокет отвечает, только пока приложение включило его (`askpass_enable` при каждом подключении и при смене
      настройки `askpass.enabled`). Нет сокета, сокет мёртвый, приложение не включило → скрипт запускает GTK-окно
      пользователя `~/.local/bin/sudo-askpass` (если есть `DISPLAY`), иначе выход 1. Отмена, 120 с без ответа,
      обрыв приложения во время ожидания → выход 1, sudo прерывается.
    - Несколько агентов: последний включившийся забирает путь атомарно (`bind` во временное имя + `rename`); старый,
      увидев чужой inode, перестаёт слушать и раз в 2 с проверяет держателя (`{"probe":true}`); держатель пропал или
      отвечает «unavailable» — забирает путь обратно. При выходе агент удаляет путь, только если это его сокет.
    - Команду, которая просит root, агент берёт сам (`/proc/<pid клиента>` → родитель `sudo` → `cmdline`), папку —
      `/proc/<pid>/cwd`, сессию tmux — по `TMUX_PANE` из скрипта и списку панелей.
    - Пароль: в renderer поле без состояния React (читается из DOM и очищается), IPC `askpass.reply` (zod: id
      16 hex, ≤ 1024 символов, без `\0\r\n`) → `askpass_reply` (`MAIN_ONLY_METHODS`) → скрипт. Агент проверяет
      параметр вручную (без эха в ошибке), не пишет его в журнал; main пишет только `id ok|cancel`. Тесты проверяют,
      что пароля нет в stderr агента, в логе main и в сторах.
    - Строку `export SUDO_ASKPASS=…` пользователь меняет сам (Настройки → Пароль sudo, кнопка «Копировать»): приложение
      не правит dotfiles. `protocol` не менялся (§7.7).
