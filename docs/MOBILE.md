# ClaudeSpace для Android (этап 8)

Решено 2026-11-19: своё приложение для Android. Оно само подключается к VM по SSH и ставит того же агента, что и
приложение на ПК. В первую версию входят чаты с терминалом и уведомления в фоне. Файлы, Git и порты будут позже.
iPhone не делаем: поставить приложение не из App Store можно только с аккаунтом Apple Developer или с переподписью
каждые 7 дней.

Статус: этапы 1 и 2 сделаны 2026-11-19 (каркас поставлен и запущен на телефоне; ПК и телефон могут работать
с одной VM одновременно), дальше этап 3.
Как собирать: `docs/DEV.md`, раздел «Приложение для Android».

## Первая версия

- **Подключение.** Хост, порт, пользователь. Приложение создаёт ключ ed25519 и показывает его публичную часть: её
  нужно один раз добавить в `~/.ssh/authorized_keys` на VM. Закрытый ключ лежит на телефоне зашифрованным ключом из
  Android Keystore. При первом подключении приложение показывает отпечаток ключа сервера, дальше сверяет его.
- **Список.** Активные сессии tmux и чаты по проектам со статусами (думает, ждёт ответа, простаивает). Новый чат в
  проекте, продолжение старого.
- **Чат.** Терминал на весь экран, тот же xterm.js, что на ПК. Текст набирается в поле внизу и уходит в Claude Code
  целиком: на Android набор прямо в терминал ломают автозамена и составной ввод клавиатуры. Над клавиатурой ряд
  клавиш: Esc, Tab, Shift+Tab, Ctrl, стрелки, Enter и цифры для ответов на запросы разрешений. Прямой набор в
  терминал остаётся переключателем.
- **Полоска Claude.** «Прервать», `/compact`, `/clear`, выбор модели. Фото и файлы с телефона в чат: файл
  загружается на VM, в поле ввода вставляется путь, как на ПК.
- **Уведомления.** «Claude ждёт ответа» и «Claude закончил» с переходом в чат, в том числе когда приложение свёрнуто
  или закрыто. Соединение в это время держит служба Android со значком в шторке. Её можно выключить в настройках,
  тогда уведомления приходят, только пока приложение открыто.

Не входят: файлы, Git, порты, несколько машин, разблокировка по отпечатку пальца.

## Как устроено

```
 Android                                                  VM
┌─────────────────────────────────────────┐   SSH   ┌─────────────────────────┐
│ служба (Kotlin, foreground service)     │═════════│ sshd                    │
│  ├ SSH (sshj): ключ, known_hosts        │         │  ├ csagent (тот же)     │
│  ├ установка агента (тот же бандл)      │         │  └ tmux attach -t …     │
│  ├ канал агента: JSON-строки            │         └─────────────────────────┘
│  ├ терминалы: exec + PTY                │
│  └ уведомления по событиям агента       │
│            ▲ мост invoke / on           │
│ WebView: React, сторы и lib общие с ПК  │
└─────────────────────────────────────────┘
```

- **Ядро живёт в службе, а не в WebView.** Android может закрыть окно приложения, а служба со значком в шторке
  продолжает держать соединение и показывать уведомления. Когда приложение открывают снова, интерфейс берёт
  состояние у службы, как renderer на ПК после перезагрузки окна.
- **Ядро почти не знает протокола агента.** Оно пересылает запросы интерфейса агенту и события обратно, а само
  разбирает только приветствие агента и события для уведомлений (`turn_done`). Сторы, разбор данных и экраны
  остаются на TypeScript, общими с ПК.
- **Мост повторяет часть каналов IPC с ПК** (`conn.*`, `agent.call`, `agent.event`, `term.*`, `settings.*`,
  `attach.upload`, `notify.*`) с теми же типами из `src/shared/ipc.ts`. Код интерфейса не знает, на ПК он работает
  или на телефоне.
- **Агент тот же.** На VM для телефона ничего не ставится и наружу ничего не открывается, как и для ПК.

Другие варианты и почему не они:
- Ядро на TypeScript внутри WebView переиспользовало бы код main целиком, но останавливается вместе с окном: когда
  Android закрывает приложение, пропадают и соединение, и уведомления.
- Node.js на Android (nodejs-mobile) позволил бы взять `ssh2` и main почти без изменений, но это отдельная среда
  выполнения, которая отстаёт от основной ветки Node. Отлаживать её падения без эмулятора тяжело.

## Разработка и проверка

- **Ядро на Kotlin** собирается и тестируется на VM как обычный JVM-модуль, без Android. Тесты поднимают встроенный
  SSH-сервер (Apache MINA SSHD) в фейковом HOME, ставят настоящего агента и открывают tmux на тестовом сокете. Так же
  устроены интеграционные тесты main с встроенным сервером ssh2.
- **Интерфейс телефона** разрабатывается в браузере: `npm run dev:mobile` отдаёт его через vite, а мост работает
  поверх нынешнего ядра main (`Connection` с `LocalTransport`) в фейковом HOME. Playwright проверяет его в размере
  телефона и снимает обе темы.
- **Эмулятора на VM нет.** Пользователь `claude` не входит в группу `kvm`, а без неё эмулятор слишком медленный.
  Добавить в группу можно только через sudo и с согласия пользователя. Пока этого нет, Android-часть (служба,
  уведомления, клавиатура) проверяется на телефоне.
- **Инструменты.** JDK и Android SDK ставятся в `~/.local/opt` без sudo, это около 4 ГБ. На раннерах GitHub Actions
  они уже есть.

## Риски и открытые вопросы

- **Ширина окна tmux.** Пока телефон активен, окно сессии сужается и на ПК: tmux подгоняет окно под последнего
  активного клиента. С Termux сейчас происходит то же самое.
- **Фоновое соединение** тратит батарею, а в режиме Doze сеть может пропадать. Служба переподключается сама. Тип
  службы `specialUse`: у `dataSync` на Android 15 лимит 6 часов в сутки.
- **Уведомления придут в три места:** на ПК, на телефон и в Telegram от хука. Позже можно добавить настройку «на
  телефон, только если ПК неактивен».
- **Ключ подписи APK** создаётся один раз и хранится вне репозитория и в секретах GitHub. Если его потерять, новая
  версия не встанет поверх старой, приложение придётся удалить и поставить заново. Нужно согласие пользователя.
- **Тестовые APK до релиза.** Как передавать их на телефон, решим на этапе 1. Например, артефактом GitHub Actions,
  но для него на телефоне нужен вход в GitHub.
- **iPhone.** Если понадобится, ядро на Kotlin придётся переписать на Swift. Интерфейс останется общим.
