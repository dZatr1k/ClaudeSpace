# ClaudeSpace — план

Настольное приложение (Electron) для Windows-ПК вместо меню `cc`: чаты, проекты и файлы с VM в одном окне,
встроенный терминал с Claude Code, кнопка RDP. Телефон — позже, отдельным этапом.

Статус: черновик плана, 2026-11-08. Ничего не реализовано.

## 1. Цели и не-цели

**Цели**
- Видеть всё сразу: активные сессии, чаты (со статусом «думает / ждёт ответа»), проекты, файлы на VM.
- Одним кликом: продолжить чат, начать новый в проекте, открыть shell / lazygit, открыть RDP.
- Работать с Claude Code во вкладках внутри приложения, без отдельного SSH-клиента.
- Сессии живут в tmux на VM: закрыл приложение или пропала сеть — Claude продолжает работать,
  при следующем запуске вкладки восстанавливаются. `cc` и ClaudeSpace видят одни и те же сессии.
- Ничего не открывать наружу: весь обмен — по SSH с ключом пользователя.

**Не-цели (пока)**
- Свой чат-интерфейс поверх Claude (рендер сообщений вместо терминала). Терминал Claude Code остаётся как есть.
- Редактор кода. Для правок — кнопка «Открыть в VS Code» (Remote-SSH).
- Мобильная версия (этап 8).
- Несколько VM / несколько пользователей. Архитектуру не закрываем, но не делаем.

## 2. Архитектура

```
 Windows-ПК                                         VM (Ubuntu)
┌──────────────────────────────┐   SSH (ключ)   ┌───────────────────────────────┐
│ ClaudeSpace (Electron)       │════════════════│ sshd                          │
│                              │  канал 1: exec │  └ csagent (Python, stdlib)   │
│  main process (Node)         │──── JSON ──────│      ├ чаты  ~/.claude/projects│
│   ├ ssh2: одно соединение    │                │      ├ сессии ~/.claude/sessions│
│   ├ IPC-шлюз (белый список)  │  канал 2..N:   │      ├ проекты ~/projects, git │
│   └ запуск mstsc / VS Code   │  shell + PTY   │      └ tmux                   │
│                              │──── байты ─────│  tmux attach -t <сессия>      │
│  renderer (React + xterm.js) │                │   └ claude --resume …         │
└──────────────────────────────┘   SFTP: файлы  └───────────────────────────────┘
```

- **Одно SSH-соединение**, несколько каналов: агент, терминалы, SFTP. Без туннелей и портов на VM.
  Отдельный туннель для приложения не нужен (для `win` с VM — по-прежнему нужен).
- **csagent** — долгоживущий процесс на VM, запускается приложением через `ssh exec`, говорит JSON-строками
  по stdin/stdout: запросы (`list chats`, `preview`, `archive`…) и события (`chat status changed`,
  `session opened`). Умирает вместе с соединением. Ставится/обновляется самим приложением
  в `~/.local/lib/claudespace/` (сверка версии при подключении).
- **Слой данных** берём из `~/.local/lib/cc-menu/ccdata.py`: он уже разбирает чаты, сессии, проекты, git,
  usage и умеет `doctor`. Шаг 1 — вынести из него общую библиотеку без форматирования для терминала, чтобы
  ей пользовались и `cc`, и csagent. `cc` не ломаем.
- **Терминал**: канал `shell` с PTY, в нём `tmux attach -t <имя>` (или `new-session`). На стороне приложения —
  xterm.js (+ addons: fit, web-links, unicode11, search, webgl). Ресайз окна → `setWindow` канала.
- **Файлы**: SFTP (листинг, превью текста/markdown/картинок, скачать/загрузить перетаскиванием).

### Стек
| Часть | Выбор | Почему |
|---|---|---|
| Оболочка | Electron + electron-vite | готовый Node в main, SSH и PTY без нативных костылей |
| UI | React + TypeScript, Tailwind | быстро собирать интерфейс, легко менять |
| Терминал | xterm.js | движок VS Code, Claude Code в нём рисуется корректно |
| SSH / SFTP | `ssh2` (Node) | чистый JS, без нативных модулей → проще сборка под Windows |
| Агент на VM | Python 3 stdlib | как ccdata.py, без зависимостей на VM |
| Сборка | electron-builder (NSIS-установщик + portable) | стандарт для Electron |
| Тесты | vitest (логика), pytest (агент), Playwright для Electron (UI-скриншоты) | |

## 3. Интерфейс

```
┌ ClaudeSpace ─────────────────────────────────────────────── ● VM  ⟳  ⚙  [RDP] ┐
│ ▸ Активные (3)        │ [claude ● MyApp] [game ◐ MyGame] [+]              │
│   ● claude   ждёт     │┌──────────────────────────────────────────────────────┐│
│   ◐ game     думает   ││                                                      ││
│ ▸ Проекты             ││   терминал: Claude Code в tmux-сессии                ││
│   MyGame   main ✱ 2ч ││                                                      ││
│   MyApp main   5м ││                                                      ││
│   webapp          1д  ││                                                      ││
│ ▸ Чаты  🔍 поиск      │└──────────────────────────────────────────────────────┘│
│   Перенос MyGame  5м │ Панель справа (скрываемая): файлы проекта | превью |   │
│   Вакансии…        1д │ git-статус | последние сообщения выбранного чата       │
│ ▸ Архив               │                                                        │
├───────────────────────┴────────────────────────────────────────────────────────┤
│ VM: CPU 12% · RAM 3.1/8 GB · диск 21/59 GB · Claude 2.x · usage сегодня 1.2M tok │
└────────────────────────────────────────────────────────────────────────────────┘
```

- **Левая панель**: Активные (tmux-сессии со статусом Claude), Проекты (`~/projects` + папки из чатов,
  ветка git и «грязность»), Чаты (заголовок, проект, время, поиск по тексту), Архив.
- **Центр**: вкладки терминалов. Вкладка = tmux-сессия. Значок статуса на вкладке.
- **Правая панель**: файлы выбранного проекта, превью файла, хвост выбранного чата, git-статус.
- **Строка состояния**: соединение, ресурсы VM, версия Claude, usage, предупреждения `doctor`.
- **Действия** (контекстное меню + горячие клавиши, командная палитра `Ctrl+K`):
  - проект: новый чат · shell · lazygit · открыть в VS Code · создать проект · клонировать репозиторий;
  - чат: продолжить (или перейти, если уже открыт) · в архив / из архива · переименовать;
  - сессия: перейти · переименовать · закрыть (с подтверждением);
  - система: RDP · usage · doctor · ресурсы.
- Язык интерфейса — русский. Тёмная и светлая темы, по умолчанию системная.

## 4. Подключение и безопасность

- Хост, пользователь и ключ берутся из `~/.ssh/config` на ПК (Host `vm`) — приложение не хранит паролей.
  Ключ с паролем → через ssh-agent Windows (OpenSSH Authentication Agent) либо запрос пароля в окне.
- Проверка ключа хоста (known_hosts), при несовпадении — отказ с понятным сообщением.
- Переподключение с экспоненциальной задержкой; терминалы при обрыве показывают «нет связи» и сами
  подцепляются к тем же tmux-сессиям.
- Electron: `contextIsolation`, без `nodeIntegration` в renderer, `sandbox`, строгий CSP, IPC — только
  перечисленные методы с проверкой аргументов. Никакой загрузки удалённых страниц.
- csagent не читает `credentials`, `settings.local.json`, `history.jsonl` (как и ccdata.py).
  Деструктивные действия (закрыть сессию, удалить) — только с подтверждением в UI.
- **RDP**: кнопка запускает существующий `C:\Scripts\connect-rdp.ps1` (туннель + mstsc с автовходом).
  Путь настраивается. Приложение не трогает сохранённый пароль RDP.

## 7. Риски

- **Формат файлов Claude Code меняется без предупреждения** (`~/.claude/projects/*.jsonl`, `sessions/*.json`).
  Защита: проверка `doctor` из ccdata.py при каждом подключении, понятное предупреждение в UI, а не падение.
- **Терминал**: вставка больших текстов, горячие клавиши, конфликтующие с Electron (`Ctrl+W`, `Ctrl+Tab`…),
  кириллица и ширина символов. Закладываем время на этапе 3.
- **Сборка под Windows** с VM — может потребоваться Node на ПК.
- **Два интерфейса к одним сессиям** (`cc` и ClaudeSpace) — одна tmux-сессия может быть открыта в обоих;
  это нормально для tmux, но размер окна берётся от меньшего клиента (настроить `window-size latest`).

## 8. Решения и открытые вопросы

Решено 2026-11-08:
1. Репозиторий на GitHub, релизы приложения публикуются там же (GitHub Releases → electron-updater).
2. Сборка под Windows — на ПК: Node.js v24 там уже есть.
3. Ключ SSH на ПК (`id_ed25519`) защищён паролем, в ssh-agent Windows не загружен (служба запущена).
   Приложение берёт ключ через ssh-agent (`\\.\pipe\openssh-ssh-agent`); если агент пуст — подсказка
   `ssh-add` или запрос пароля в окне. Пароль не сохраняем.
4. `cc` остаётся запасным вариантом.
