# ClaudeSpace: инструкции для Claude Code

Electron-приложение для Windows, через которое работают с Claude Code на Linux-машине по SSH, и агент на Python,
который приложение само ставит на эту машину. Подробности:
- [docs/DEV.md](docs/DEV.md): запуск, тесты, архитектура, выпуск, раздел «Что не проверено»;
- [docs/DESIGN.md](docs/DESIGN.md): экраны, сценарии, визуальный стиль;
- [docs/BACKLOG.md](docs/BACKLOG.md): замечания пользователя и их статус.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev:vm` | dev-запуск на Linux (`--no-sandbox`); на Windows `npm run dev` |
| `npm run typecheck`, `npm run lint` | `tsc` strict; ESLint и Prettier (`npm run format` исправляет формат) |
| `npm test` | тесты агента (unittest) и vitest |
| `npm run test:e2e` | Playwright `_electron`, снимки в `docs/screenshots/`; нужны X-дисплей и свежий `out/` (`npm run build`) |
| `npm run splash` | загрузочный экран отдельно от приложения, `127.0.0.1:5180` |
| `npm run release -- X.Y.Z` | версия в `package.json`, коммит `Release vX.Y.Z` и тег; ничего не пушит |

## Перед тем как сдать работу

- Проходят `npm run typecheck && npm run lint && npm test`.
- Если менялся интерфейс, прогнать e2e и посмотреть снимки в обеих темах.
- Новое поведение покрыть тестом рядом с похожими: агент в `agent/tests/`, логика в `tests/unit/`, связка main и
  агента в `tests/integration/`, сценарий в окне в `tests/e2e/`.
- Документацию обновлять в том же коммите: `CHANGELOG.md` (раздел следующей версии), `docs/DEV.md` (как устроено,
  что не проверено), `docs/BACKLOG.md`, если задача оттуда.

## Правила

- **Интерфейс только через скиллы antislop** (плагин [anti-slop](https://github.com/miqdadbadjuber/anti-slop)),
  обязательно и каждый раз:
  - вёрстка, компоненты, цвета, анимация: `antislop:antislop-ui`;
  - любой текст в интерфейсе (подписи, подсказки, сообщения, пустые состояния): `antislop:antislop-copywriting`;
  - вместе с ними всегда ядро `antislop:antislop`. Направление и токены берутся из `docs/DESIGN.md` §5, перед сдачей
    пройти Delivery Gate из ядра.
- **Репозиторий публичный.** В код, тесты, документацию и снимки не попадают личные данные: имена пользователей и
  машин, IP-адреса, пути с личных компьютеров, названия чужих проектов. Перед коммитом проверить `git diff --cached`.
  e2e работает с фейковым `HOME`, поэтому его снимки чистые. Снимки с настоящими данными не коммитить.
- **Не мешать установленному приложению.** В локальном режиме приложение (dev или собранное) ставит агент в
  `~/.local/lib/claudespace/` и подключается к настоящему tmux. Если на машине уже работает ClaudeSpace, запускать
  с фейковым `HOME`, своим `CLAUDESPACE_USER_DATA` и отдельным сокетом tmux (`connection.tmuxSocket` в настройках),
  как это делает `tests/e2e/smoke.spec.ts`. `npm run agent:install` перезаписывает агент, которым пользуется
  установленное приложение.
- Тесты, которые создают сессии tmux, работают на своём сокете (`tmux -L claudespace-test-*`) и убивают его в конце.
  Чужие сессии не трогать.
- **Защиту не ослаблять** (подробно в `docs/DEV.md`, раздел «Архитектура»): у агента нет метода «выполнить
  команду», запрет-список файлов проверяет `agent/tests/test_security.py`; IPC идёт только через каналы из
  `src/shared/channels.ts` с проверкой zod; окно работает с `contextIsolation` и `sandbox`.
- Агент пишется только на стандартной библиотеке Python 3.8+: на машине пользователя для него ничего не ставится.
- В `dependencies` только то, что нужно main-процессу собранного приложения. Всё, что нужно renderer, лежит в
  `devDependencies`: vite собирает это в бандл.
- Интерфейс и документация на русском. `CHANGELOG.md`, коммиты и комментарии в коде на английском.

## Выпуск

Только по прямой просьбе владельца репозитория. `npm run release -- X.Y.Z`, затем `git push origin main vX.Y.Z`.
Тег запускает `.github/workflows/release.yml`: тесты, установщик для Windows и AppImage, публикация релиза.
Установленные приложения находят новую версию сами. Тег должен совпадать с версией в `package.json`, иначе сборка
падает.
